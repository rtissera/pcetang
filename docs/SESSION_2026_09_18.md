# Session log — 2026-09-17/18

Everything below was measured, on real hardware or in simulation. Nothing is estimated.

## Headline

Five PC Engine CD games play on Tang Console 60K, SuperGrafx runs for the first time, and a
single bitstream now carries the complete PC Engine feature set — HuCard, CD-ROM², Super
CD-ROM², Arcade Card, SuperGrafx, CD-DA and ADPCM — at 0 setup / 0 hold violations.

## CD-DA: three real bugs, four games fixed

Symptom: R-Type Complete CD went black after its intro, Prince of Persia never started. Both
parked in SCSI COMMAND phase after command `0xD9` (SAPEP), toggling `$1802` forever — waiting for
an end-of-audio notification that never came.

1. **The audio end position was thrown away.** `cd_bridge` read SAPEP's play mode and ignored the
   end LBA, so playback never stopped, looped or reported completion. Mednafen and MAME both
   stream until `lba > end` and then loop or send STATUS GOOD; in our stack that status *is* the
   interrupt, because cd.vhd raises the transfer-done flag when the status phase begins.
2. **Addressing was decoded wrongly in both commands.** The mode is `cdb[9] & 0xC0` — `0x00` raw
   LBA from cdb[3..5], `0x40` BCD AMSF from cdb[2..4], `0x80` BCD track. This port used different
   bits *and* the wrong bytes. R-Type asks for AMSF 01:27:23 (LBA 6398) and got LBA 75555.
3. **Every audio fetch went out one sector late** — the audio path advanced `read_lba` in the same
   clocked assignment that raised the request.

Result on hardware: **R-Type Complete CD, Prince of Persia and Rondo all play through**; Bonk III
unchanged. Tag `pcecd-cdda-endpos-2026-09-17`.

## HDMI: tearing fixed, shimmer understood

"Picture mostly okay but scrambled line by line" was the 2-line ping-pong buffer being overwritten
while read: a source line takes 63.70 µs to write and the reader showed a line across 44.37 µs, so
the writer returned to the buffer still being read.

Measured with a new Verilator harness (`sim/hdmi/`), identical stimulus:

| | torn output lines |
|---|---|
| shipping 2-buffer design | **17.2%** |
| 3 buffers + adopt-at-boundary | **2.7%** (only 1.1% inside the visible 720 lines) |

Confirmed on hardware: *"works, better, I can barely see any corruption."* Cost: 2 BSRAM blocks.

The residual shimmer is **arithmetically unavoidable**: exact frame lock needs 755.16 output lines
per frame and a vertical total must be an integer, so the servo dithers 755/756 forever. An
exhaustive PLL search found no setting that lands on a whole number of lines. Vertical
interpolation halves the shimmer amplitude (mean |Δ| 68.5 → 32.9 of 255) but softens fine
horizontal detail. A "pull reader" design that would fix it properly is parked, not working, on
`fix/hdmi-pull-reader`.

## SuperGrafx: first run ever on this core

`LITE => 0` plus `syn_preserve` (which frees the 9 BSRAM blocks SuperGrafx needs) builds at 0/0,
42.945 MHz, 110/118 BSRAM. The firmware now accepts `.sgx` files — it refused them before.

| game | result |
|---|---|
| Daimakaimura | boots and plays, partial graphic corruption |
| Aldynes | boots and plays, graphic corruption |
| Battle Ace | boots and plays, no corruption, missing sprites |
| 1941 Counter Attack | black screen |

1941 is localised: trace tag `0xD2` shows the CPU running and writing the VDC heavily, but **2
vblank interrupts against thousands for the others, with IRQ1 stuck asserted** — spinning in an
interrupt it cannot clear. With `LITE => 0`, `IRQ1_N => VDC0_IRQ_N and VDC1_IRQ_N`, so an
interrupt raised by the second VDC can only be cleared by reading *its* status. That AND gate is
where to look.

## Per-board configuration, measured

| | Nano 20K | Primer 25K | Console 60K |
|---|---|---|---|
| shipping | 0/0, 42.466 MHz, 90% logic | 0/0, 42.907 MHz, 94% logic | 0/0, 43.056 MHz, 32% logic |
| Arcade Card | not reachable (needs 26 BSRAM it lacks) | **0/0 at +3.3%** via on-chip VRAM | **0/0**, stock donor code |
| SuperGrafx | no room | no room | **0/0**, +0.76% with `syn_preserve` |

The Primer 25K result is the surprise: `syn_preserve` frees 9 BSRAM → VRAM moves on-chip →
3349 LUTs freed → the Arcade Card fits, with the best margin that board has ever had.

Measured dead ends, recorded so they are not retried: CE-strobe request detection (timing worse),
`AC_SLIM` one shared adder (33 LUTs), the Arcade Card registered bus (nothing), PSG Path A on Nano
20K (399 violations), PSG Path 0 on Primer 25K (fails routing at every placement).

- DD2's title-screen voice is cut; Rondo's ADPCM voices unconfirmed.
